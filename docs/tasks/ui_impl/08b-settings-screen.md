# ui_impl 08b: schema-driven settings screen (all four tabs, draft, apply)

Design source: `docs/ui-design/03-settings.md` (sections 1, 3 "Graphics settings" layout and the shared-geometry paragraph, 4, 5, 6, 8, and the Graphics preset paragraph), `docs/ui-design/settings-schema.json`, `docs/ui-design/DATA_CONTRACTS.md` (`SettingsView`, `SettingAvailability`, `settings.tab`, `settings.close`, `settings.apply`). Web only; card 08 builds `SettingsService` and the Godot routes in parallel and copies the schema to `ui/web/public/settings-schema.json` (create that copy yourself if it is not there yet: byte-for-byte from `docs/ui-design/settings-schema.json`). The settings routes are `/settings/graphics`, `/settings/controls`, `/settings/social`, `/settings/others`; Godot navigates between them after `settings.tab`.

## Decisions for this card (supervisor)
- Rows are generated from the schema; no hand-written per-setting components. Bindings are shown read-only in this card (rebind/capture comes later): the row shows the binding chip and a disabled `Change` button with `title="Rebinding comes in the next update"`.
- `settings.capture`, `settings.display_confirm` are not used here. Display preview UI comes later.
- Keys never reach the page in game (mouse only), but implement keyboard behaviour anyway where `lib/ui` already does it (dev preview and future focus support).
- Lobby and Pause `Settings` buttons become enabled and send `settings.open` (remove the `Coming later` hint there).

## Steps
1. `schema.ts`: `import schemaJson from '../../../public/settings-schema.json'` (check the relative path; enable `resolveJsonModule` only if `tsc` needs it and report). Types `SettingEntry` (all schema fields, `type` as a union of the 8 types), `SETTINGS: SettingEntry[]`, `entriesFor(tab)`, `groupsFor(tab)` (in order of first appearance), `defaultsFor(keys)`. `schema.test.ts`: every entry has a `group`; the 4 tabs exist; and the runtime copy equals the design copy (read both files with `node:fs` and compare the parsed JSON deep-equal; path from `import.meta.url` or `process.cwd()` = `ui/web`).
2. `format.ts`: `optionLabel(key, option)` (humanized: `msaa_4x` -> `MSAA 4×`, `fxaa` -> `FXAA`, `push_to_talk` -> `Push to talk`, `1920x1080` -> `1920 × 1080`, `native` -> `Native`, `unlimited` -> `Unlimited`, frame caps `120` -> `120 FPS`, `en` -> `English`, others capitalised words); `valueText(entry, v)` for sliders: `%` for `render_scale`, `ui_scale` and every `*_volume`; `°` for `fov`; `s` for `notifications_duration`; `dBFS` for `voice_input_threshold`; `gamma` two decimals; `mouse_sensitivity` four decimals; `bindingText(code)` (`KeyW` -> `W`, `Digit1` -> `1`, `Ctrl+KeyB` -> `Ctrl+B`, `MouseLeft` -> `LMB`, `MouseRight` -> `RMB`, `Space` -> `Space`, null -> `Unbound`).
3. `presets.ts`: `PRESET_KEYS = ['render_scale','shadows','textures','anti_aliasing','view_distance']`; `PRESETS` low/medium/high exactly as the Graphics paragraph in 03-settings.md; `applyPreset(draft, preset)` writes the five values (`custom` writes nothing); `withManualChange(draft, key, value)`: when `key` is a preset member and the result no longer matches the selected preset, set `quality_preset = 'custom'`. `presets.test.ts` covers both.
4. `settingsStore.ts` (zustand): `view: SettingsView | null`, `draft: Record<string, SettingValue>`, `setView(view)` (when the new revision differs from the draft's base revision, rebase: keep draft values only for keys whose persisted value did not change, drop the others and remember them in `conflicts`), `edit(key, value)` (through `withManualChange`; `quality_preset` through `applyPreset`), `discard()`, `stageDefaults(keys)`, `changedKeys()`, `patch()`.
5. `SettingRow.tsx` by type, at the shared row geometry (48 px rows, 4 px gap, label 296 px, control 496 px): `boolean` -> `Toggle`; `enum` -> `Dropdown` with `optionLabel`; `integer`/`number` -> `Slider` (`min`/`max`/`step`, `format` = `valueText`); `device` -> `Dropdown` from `view.devices.input|output` (`voice_input_device` uses input); `integer_array` -> list of `Player <id>` or `No muted players`; `binding` -> `KeyHint`-style chip with `bindingText` + disabled `Change` button; `action` -> a secondary button (`reset_controls` -> confirm then `stageDefaults` of all controls-tab bindings and mouse rows; `reset_all` -> confirm then `stageDefaults` of every non-action key; `credits` -> `Modal` "Credits" listing `FinalRun`, `Kenney Mini Characters (CC0)`, and "See assets/CREDITS.md for the full list"). A changed row shows a 2 px amber left edge and the text `Changed` (sr-only + visible dot). Capability: `visible: false` -> not rendered; `enabled: false` -> control disabled + tag `Coming later` (reason `coming_later`) or `Not available` (other reasons). `restart: true` rows show `Applies next launch`.
6. `SettingsScreen.tsx` (positions from the Graphics layout table; used for all four tabs):
   - Header (A01-A04): `Back` (secondary) -> if dirty, `Modal` `Discard changes?` (`Keep editing` safe focus, `Discard`) then `request('settings.close')`; title `Settings`; context label `From lobby` / `From pause` is not known to the page: show `Changes apply after Apply` instead.
   - Tabs (A05-A09): `TabBar` with Graphics/Controls/Social/Others; selecting sends `request('settings.tab', { tab })` (the route change comes from Godot); disabled while applying.
   - Body: group rail (A11, buttons 184 x 36 with 4 px gaps, click scrolls the list to that group's first row) and the control list (A12, `overflow-y-auto`, rows from `entriesFor(tab)` filtered by capability `visible`, repacked; a group heading row is not drawn, the rail is the heading).
   - Footer (A25-A29): status text (`Loading settings` before the first view; `Saved` when clean; `<n> changes` when dirty; `Applying` while pending; error text for `stale_revision` -> `Settings changed elsewhere. Your other changes were kept.`, `binding_conflict` -> `Two actions use the same key.`, `save_failed` -> `Could not save settings.`, others -> `Could not apply settings.`; append ` · Restart needed for: <labels>` when `pendingRestart` is non-empty); `Reset` (stage defaults for the current tab after a confirm `Reset <Tab> settings?`), `Discard` (disabled when clean), `Apply` (primary, disabled when clean; `request('settings.apply', { revision, patch })`, `loading` while pending; on success the next `settings` snapshot arrives from Godot and clears the draft for applied keys).
   - Before the first `settings` snapshot: tabs and 8 skeleton rows, footer buttons disabled.
7. `router.tsx`: `/settings/$tab` route (or four static routes) -> `SettingsScreen` with the tab; hide `HudScreen` on settings routes. `main.tsx`: wire `setSettings` -> `settingsStore.setView`; dev preview `#settings` sets `DEMO_SETTINGS` (defaults from the schema, revision 1, capabilities: everything visible/enabled except the schema's capability entries, which follow the decision rules: `coming_later` disabled, `hidden` invisible) and navigates `/settings/graphics`.
8. Lobby and Pause: `Settings` enabled, sends `request('settings.open')`; update their tests.
9. `SettingsScreen.test.tsx`: renders Graphics rows from the schema (e.g. `Display mode`, `Field of view`); changing FOV marks the row changed and enables Apply; Apply sends `settings.apply` with `{ revision: 1, patch: { fov: <new> } }`; choosing quality preset `low` stages the five preset values; changing `shadows` after a preset switches the preset to `Custom`; a `coming_later` row is disabled with the tag; a `hidden` row is absent; Discard clears the draft; Back with a dirty draft asks first; tab click sends `settings.tab`.
10. Checks: `npm run test`, `npm run build` (in `ui/web/`). Confirm `ui/dist/settings-schema.json` exists after the build.
