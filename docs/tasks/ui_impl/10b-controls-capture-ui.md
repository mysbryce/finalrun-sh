## Decisions for this card (supervisor)
- Binding codes (shared with Godot): `KeyA`..`KeyZ`, `Digit0`..`Digit9`, `F1`..`F12`, `Numpad0`..`Numpad9`, `Space`, `Tab`, `Enter`, `Escape`, `Backspace`, `CapsLock`, `Insert`, `Delete`, `Home`, `End`, `PageUp`, `PageDown`, `ArrowUp`, `ArrowDown`, `ArrowLeft`, `ArrowRight`, `Backquote`, `Minus`, `Equal`, `BracketLeft`, `BracketRight`, `Backslash`, `Semicolon`, `Quote`, `Comma`, `Period`, `Slash`, `ShiftLeft`, `ShiftRight`, `ControlLeft`, `ControlRight`, `AltLeft`, `AltRight`, `MouseLeft`, `MouseRight`, `MouseMiddle`, `MouseBack`, `MouseForward`, `MouseMotion`; optional `Ctrl+`, `Alt+`, `Shift+` prefixes in that order. The list is for `bindingText` and Godot parity only: do not validate replies against it.
- Godot does the capture (keys never reach the page in game). Left click is the UI pointer and is never captured by Godot, so the dialog offers a `Use left click` button.
- Fixed bindings: `FIXED_BINDINGS = ['bind_look', 'bind_pause']` (export it from `features/settings/schema.ts`). Their row shows the chip and a `Fixed` tag, no `Change` button.
- Conflict context: a binding conflicts with another binding key (any binding in the schema, including coming-later and hidden ones) holding the same value in the draft-merged values, where keys whose `capability` is `debug_shortcuts` form their own context. Same rule as Godot's `binding_conflict`.
- `Replace` stages the new value and `null` for the other key in one go; it is disabled (with the reason text `That action cannot be unbound.`) when the other key is fixed or its availability is not `enabled` (the host would reject the patch as `unsupported`).
- `Clear` stages `null`. For `bind_move_forward`, `bind_move_left`, `bind_move_back`, `bind_move_right` and `bind_fire` it asks first (confirm view below).
- The conflict body names only the other action (supervisor simplification of section 5 "show both action labels": the dialog title already names this action).

3. `bindings.ts`: `MOVEMENT_AND_FIRE` (the 5 keys that need confirm), `bindingContext(entry)` (`'debug'` when `entry.capability === 'debug_shortcuts'`, else `'game'`), `findConflict(key, code, values): string | null` (the other key in the same context with the same non-null value, schema order; `values` = draft merged over persisted), `canUnbind(key, availability)` (false for fixed or not-enabled keys). Tests in `bindings.test.ts`: `KeyW` for `bind_interact` conflicts with `bind_move_forward`; `KeyY` for `bind_hotbar_1` does not conflict with debug `bind_sell_loot`; `Ctrl+Digit1` for `bind_join_house` conflicts with `bind_join_motel`; null never conflicts; the key itself is ignored; `canUnbind('bind_pause', ...)` false; `canUnbind('bind_reload', {visible: true, enabled: false, reason: 'coming_later'})` false.
4. `CaptureDialog.tsx`, props `entry: SettingEntry`, `values: Record<string, SettingValue>`, `capabilities: SettingsView['capabilities']`, `onStage(patch: Record<string, SettingValue>)`, `onClose()`. Availability lookups use `capabilities[k] ?? ALWAYS_AVAILABLE` (import from `./SettingRow`).
   - Pending capture handling (avoids self-closing on the host's null reply to our own cancel, double cancels, stale replies and StrictMode double mount): a `pendingRef`; helper `cancelCapture()` = if `pendingRef.current`, set it false and `request('settings.capture_cancel').catch(() => undefined)`. The mount effect: `let live = true; pendingRef.current = true;` then `request('settings.capture', { key: entry.key }, 20000)`; its `.then`/`.catch` return early unless `live && pendingRef.current`, and set `pendingRef.current = false` before acting. The effect cleanup: `live = false; cancelCapture()`. Every button that ends capture (`Cancel`, `Use left click`, `Clear`) calls `cancelCapture()` first. An error reply leaves `pendingRef.current = false`, so closing the error view sends nothing.
   - Views, each rendered as `<Modal key={view} dismissible onDismiss={<the view's safe action>} ...>` so remounting focuses the safe button:
     - `capture`: title `Rebind <label>`. Body (fits the fixed 512 x 256 Modal, about 132 px): row 1 `Press a key or mouse button. Esc cancels.`; row 2 `Current:` + the binding chip (reuse the chip classes from `SettingRow.tsx`) with `<n> s` right-aligned (`aria-live="polite"`, counts down once per second from 15, stops at `0 s`; the page does not close on 0, it waits for the host's null reply or the 20 s request timeout); row 3 `Use left click` and `Clear` buttons (`variant="secondary" size="compact"`). Primary `Cancel` (`cancelCapture()`, `onClose()`); safe action = `Cancel`.
     - `conflict`: title `Key already in use`; body `<bindingText(code)> is used by <other label>.` plus `That action cannot be unbound.` when Replace is disabled; secondary `Cancel` (close, stage nothing; safe action); primary `Replace` (`onStage({[key]: code, [other]: null})`, `onClose()`; `disabled` per the decision).
     - `confirm`: title `Leave <label> unbound?`; body `<label> will have no input until you bind it again.`; secondary `Keep` (close without staging, no new capture; safe action); primary `Unbind` (`onStage({[key]: null})`, `onClose()`).
     - `error`: body `Another rebind is in progress.` (`busy`), `Rebinding is not available right now.` (`not_available`), `Could not capture input.` (timeout or anything else); single primary `Close` (safe action).
   - Reply handling: a non-string `binding` is null. Order: null -> `onClose()`; same as the current value -> `onClose()` without staging; `findConflict` finds another key -> `conflict` view; else `onStage({[key]: code})` and `onClose()`.
   - `Use left click`: `cancelCapture()`, then the same reply handling with `MouseLeft`.
   - `Clear`: `cancelCapture()`; current value already null -> `onClose()`; key not in `MOVEMENT_AND_FIRE` -> `onStage({[key]: null})`, `onClose()`; else the `confirm` view.
5. `SettingRow.tsx` binding case: new required prop `onCapture: () => void`. `Change` button (secondary, compact) enabled when the row is enabled, not locked and not fixed; it calls `onCapture()`. Fixed keys: no button, and `tag = 'Fixed'` in the existing meta line (the same span as `Coming later`). Remove the old disabled button and its title.

While `captureKey` is set: `Back`, tabs and footer buttons are disabled and the root `onKeyDown` Escape handler does nothing (Escape belongs to the dialog).
