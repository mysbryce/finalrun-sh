## Decisions for this card (supervisor)
- Behaviour change (intended): today 1-4 travel and 5 sells in every build. After this card 1-6 select hotbar slots; travel is Ctrl+1..4 and sell is Y, debug builds only (schema `bind_join_*`, `bind_sell_loot`, capability `debug_shortcuts` = `OS.is_debug_build()`). P creates a party. All controls now come from the settings schema: if `res://ui/dist/settings-schema.json` fails to parse there are no bindings (accepted; the smoke check below guards it).
- Binding values are physical codes (layout independent, same names as the web `KeyboardEvent.code`), optionally prefixed `Ctrl+`, `Alt+`, `Shift+` in that order. Godot matches on `InputEventKey.physical_keycode`, never `keycode`. The full code list (both sides use exactly this):
  - `KeyA`..`KeyZ` -> `KEY_A`..`KEY_Z`; `Digit0`..`Digit9` -> `KEY_0`..`KEY_9`; `F1`..`F12` -> `KEY_F1`..`KEY_F12`; `Numpad0`..`Numpad9` -> `KEY_KP_0`..`KEY_KP_9`.
  - `Space` `KEY_SPACE`, `Tab` `KEY_TAB`, `Enter` `KEY_ENTER` (and `KEY_KP_ENTER` reads as `Enter`), `Escape` `KEY_ESCAPE`, `Backspace` `KEY_BACKSPACE`, `CapsLock` `KEY_CAPSLOCK`, `Insert` `KEY_INSERT`, `Delete` `KEY_DELETE`, `Home` `KEY_HOME`, `End` `KEY_END`, `PageUp` `KEY_PAGEUP`, `PageDown` `KEY_PAGEDOWN`, `ArrowUp` `KEY_UP`, `ArrowDown` `KEY_DOWN`, `ArrowLeft` `KEY_LEFT`, `ArrowRight` `KEY_RIGHT`.
  - `Backquote` `KEY_QUOTELEFT`, `Minus` `KEY_MINUS`, `Equal` `KEY_EQUAL`, `BracketLeft` `KEY_BRACKETLEFT`, `BracketRight` `KEY_BRACKETRIGHT`, `Backslash` `KEY_BACKSLASH`, `Semicolon` `KEY_SEMICOLON`, `Quote` `KEY_APOSTROPHE`, `Comma` `KEY_COMMA`, `Period` `KEY_PERIOD`, `Slash` `KEY_SLASH`.
  - Bare modifier keys (never with a prefix): `ShiftLeft`/`ShiftRight` `KEY_SHIFT`, `ControlLeft`/`ControlRight` `KEY_CTRL`, `AltLeft`/`AltRight` `KEY_ALT`, side from `InputEventKey.location` (`KEY_LOCATION_RIGHT` -> Right, anything else -> Left).
  - Mouse: `MouseLeft` `MOUSE_BUTTON_LEFT`, `MouseRight` `MOUSE_BUTTON_RIGHT`, `MouseMiddle` `MOUSE_BUTTON_MIDDLE`, `MouseBack` `MOUSE_BUTTON_XBUTTON1`, `MouseForward` `MOUSE_BUTTON_XBUTTON2` (modifier prefixes allowed). Wheel buttons are never codes.
  - `MouseMotion` is the fixed Look binding: valid only as the value of `bind_look`, never produced by an event, never dispatched, never prefixed.
  - Meta/Windows keys and anything not listed produce `""` (unsupported).
- No `InputMap` (its modifier matching makes bare modifier bindings stick on release). `lib/utils/InputBindings.gd` does code <-> event and lookup. Action names are the setting keys (`bind_interact`, ...).
- Supervisor exception to the `lib/utils` no-state rule: `InputBindings` keeps the active binding table in `static var`s because Main and Player (features/, which may not import ui/) both need it. Its only writers are `set_bindings` and `clear`. Put a `## Exception:` doc comment saying so at the top of the file.
- Lookup for a pressed event: exact code with modifiers first; if nothing is bound to it, the bare code without modifiers (Shift+E still interacts while sprinting; in release builds Ctrl+1 falls back to hotbar 1). Held movement checks only the base key/button and cannot tell left from right modifiers (`# ponytail:` comment).
- Only enabled bindings are dispatched: `SettingsService.active_bindings()` drops null values, the fixed bindings and keys whose capability makes them not enabled (coming later: jump, sprint, crouch, aim, reload, map, ping, push to talk, chat, emote, help; the debug shortcuts in release builds). `set_bindings` walks the dictionary in order and keeps the first action for each code (`# ponytail:` normally only possible across the debug context; a hand-edited cfg can also collide).
- Validation tightening in `SettingsService`: a binding value must also pass `InputBindings.is_valid_code` (rejects `KeyFoo`, `Ctrl+ShiftLeft`, `Shift+MouseMotion`); `MouseMotion` is valid only for `bind_look`; `load()` always uses the schema default for keys in `GameConst.FIXED_BINDINGS` (a stored `bind_look = "KeyL"` is ignored).
- Fixed bindings: `GameConst.FIXED_BINDINGS: PackedStringArray = ["bind_look", "bind_pause"]`. Escape stays a hard-coded `KEY_ESCAPE` check in Main. `apply_patch` returns `unsupported` when the patch changes a fixed binding's value (an equal value passes, so Reset still works).
- Mouse delivery: the `Instances` `SubViewportContainer` gets `mouse_filter = Control.MOUSE_FILTER_PASS`, so clicks still reach the SubViewport (Player fire, camera recapture) and also reach `Main._unhandled_input` (mouse-bound actions).
- Capture: Godot captures one input for `settings.capture {key}` and replies `{binding: code}` or `{binding: null}` (Escape, Cancel, 15 s timeout, focus loss, settings screen no longer open, page reload). Rules (pure class `ui/settings/BindingCapture.gd`):
  - Ignored (not done, pending modifier unchanged): echo, Meta keys, `Alt+Tab`, `Alt+F4`, unsupported codes, non-modifier key releases, mouse button releases, `MouseLeft` press, wheel buttons, mouse motion.
  - Escape press -> done, `null`.
  - Modifier key press -> it becomes the pending modifier (the latest press replaces an earlier one; on Windows AltGr sends a fake left Ctrl, then right Alt), not done. A modifier release finishes with the bare code (`ControlLeft` etc.) only when its code equals the pending code; other modifier releases are ignored.
  - Any other key press -> done with the code including the held modifiers (`event.ctrl_pressed`/`alt_pressed`/`shift_pressed`).
  - Other mouse button press (Right, Middle, Back, Forward) -> done with its code (with modifiers).
  - Consume: every key event and every mouse button event except `MouseLeft` (left click is the UI pointer; the page's Cancel button needs it; the page offers "Use left click"). Wheel is consumed. Mouse motion is not consumed. Consuming in `Main._input` keeps Main's Tab, Esc and action dispatch away from the event; Player stays inert through its captured-mouse guards (Settings frees the cursor), which must stay.
- Capture errors, checked in this order: `busy` (`_capture != null`), `not_available` (`not _hud.is_settings_open()`), then `SettingsService.capture_error(key)`: `bad_params` for an unknown key, a non-binding or a fixed key, `not_available` for a binding whose capability is not enabled, `""` otherwise. An unbound (null) binding can be captured.
- Hotbar 1-6 select a local active slot shown in HudState `activeSlot` (0-based). `# ponytail:` server validates the equipped item when items are Resources (Phase 3); firing still uses the pistol.
- `bind_party_create` reuses `_on_party_action("create", 0)`. `bind_reload` (B) has no handler yet (coming later). R stays Revive.
- HUD interact prompts still say "E ..." from the prompt strings; following the bindings comes with the HUD refine card (`# ponytail:` comment in `Hud.interact_of`).

## Steps
1. `GameConst.gd` `# Input bindings`: `FIXED_BINDINGS`, `CAPTURE_TIMEOUT_MS: int = 15000`, `ACTION_MOVE_FORWARD := "bind_move_forward"`, `ACTION_MOVE_LEFT := "bind_move_left"`, `ACTION_MOVE_BACK := "bind_move_back"`, `ACTION_MOVE_RIGHT := "bind_move_right"`, `ACTION_FIRE := "bind_fire"`, `LOOK_BINDING_CODE := "MouseMotion"`; move `BINDING_MODIFIERS` and `BINDING_SEPARATOR` here from `SettingsService.gd` and use them from both files.
2. `lib/utils/InputBindings.gd`, `class_name InputBindings extends RefCounted`, all static:
   - `static func code_from_event(event: InputEvent) -> String` per the code list (modifier prefixes only for non-modifier keys and mouse buttons; `""` when unsupported).
   - `static func event_from_code(code: String) -> InputEvent`: inverse; a new event on every call; sets `physical_keycode` (never only `keycode`) or `button_index`, the `ctrl_pressed`/`alt_pressed`/`shift_pressed` flags from the prefixes, and `location` `KEY_LOCATION_LEFT`/`KEY_LOCATION_RIGHT` for bare modifiers; `null` for `MouseMotion`, `""`, unknown codes, a prefixed bare modifier or a prefixed `MouseMotion`. Build the lookup tables once (static vars filled on first use).
   - `static func is_valid_code(code: String) -> bool`: `code == GameConst.LOOK_BINDING_CODE` or `event_from_code(code) != null`.
   - `static func set_bindings(bindings: Dictionary) -> void` (action -> code), `static func clear() -> void`, `static func action_for_event(event: InputEvent) -> String` (only a pressed, non-echo `InputEventKey` or a pressed non-wheel `InputEventMouseButton`; exact code then bare code; `""` otherwise), `static func is_held(action: String) -> bool` (key: `Input.is_physical_key_pressed(keycode)`; mouse: `Input.is_mouse_button_pressed(button)`; unbound: false), `static func code_for(action: String) -> String` (`""` when unbound).
3. `ui/settings/BindingCapture.gd`, `class_name BindingCapture extends RefCounted`: `var request_id: int`, `var key: String`, `func _init(id: int, setting_key: String, now_ms: int)`, `func feed(event: InputEvent) -> Dictionary` returning `{"done": bool, "binding": Variant, "consume": bool}` per the rules, `func timed_out(now_ms: int) -> bool` (`now_ms - started >= GameConst.CAPTURE_TIMEOUT_MS`).
