# ui_impl 04: splash and boot flow (title dwell, interface load, connect, retry/quit)

Design source: `docs/ui-design/01-splash.md` (read all of it) and `docs/ui-design/DATA_CONTRACTS.md` (`BootView`, `boot.skip`, `boot.retry`, `app.quit`). README step 4. Card 03 already added the TS types, the bridge setter `setBoot`, and `Hud.publish(type, data)` with replay on page `ready`.

## Decisions for this card (supervisor)
- Stage order on the rail stays Assets -> Interface -> Connection, but there is no asset preload today: the Assets stage is complete at start and `progress` stays `null` (`# ponytail:` comment: real preload progress when there is something to preload; then add the 30 s asset watchdog).
- The connection starts only after the page is `ready` AND the title dwell is over (or skipped). So the server's map-load RPC can never arrive before the UI is ready; no pending-work queue needed.
- After connecting: phase `ready`, the boot snapshot is cleared and the route goes to `/` (the existing HUD; the transfer screen comes in a later card).
- No CEF (`Hud.can_use_browser()` false, e.g. headless): skip the boot UI and connect immediately, as today.
- Native fallback: if the page never sends `ready` within the CEF timeout, Main shows a plain Godot UI (label + Retry + Quit buttons) in its own `CanvasLayer` above the Hud (the Hud is a `CanvasLayer` on layer 1 with a full-screen browser texture). Retry reloads the browser page and restarts the CEF watchdog.
- Keys stay with the game (the browser has `FOCUS_NONE`, see `docs/design/WEB_UI.md`): Enter-to-skip is handled by `Main._unhandled_input` while booting, not by the page. The page's buttons are used with the mouse (panel input frees the cursor).
- `boot.skip` / `boot.retry` / `app.quit` always reply ok `{}` from the static `Hud.route_request`; the contract's `not_available` / `busy` errors are deferred (`# ponytail:` comment there: Main ignores requests that do not apply).
- Clock: every `BootFlow` call uses `now = Time.get_ticks_msec()` (not `_client_now_ms()`).

## Steps
### Godot
1. `GameConst.gd`, new block `# Boot`: `BOOT_TITLE_DWELL_MS: int = 800`, `BOOT_SKIP_AFTER_MS: int = 250`, `BOOT_CEF_TIMEOUT_MS: int = 15000`, `BOOT_CONNECT_TIMEOUT_MS: int = 12000`, `BOOT_FALLBACK_LAYER: int = 10` (CanvasLayer of the native fallback), `DEFAULT_SERVER_HOST: String = "127.0.0.1"` (keep using `PORT` for the port).
2. `main/BootFlow.gd`: `class_name BootFlow extends RefCounted`, pure logic, no nodes, time passed in as `now_ms`.
   - State: `phase: String` (`"title"`, `"cef"`, `"connecting"`, `"ready"`, `"failed"`), `error` (`Variant`, null or a `BootError` string), `build_id`, internal start/phase timestamps, `title_done`, `page_ready`.
   - `func start(now_ms: int, build_id: String) -> void` (phase `title`).
   - `func skip(now_ms: int) -> bool`: allowed only in `title`/`cef` before the dwell ends and once `now_ms - start >= BOOT_SKIP_AFTER_MS`; marks the dwell done; returns whether it took effect.
   - `func on_page_ready(now_ms: int) -> void`: sets `page_ready`. Late page: if phase is `failed` with error `cef_timeout`, go back to phase `cef` with error null, so the next `tick` can connect.
   - `func tick(now_ms: int) -> String`: returns an action for Main: `"connect"` when dwell done and page ready and phase is `title`/`cef` (phase -> `connecting`); `"fail_cef"` when, in `title` or `cef`, the page is not ready `BOOT_CEF_TIMEOUT_MS` after the CEF timer started (the timer starts in `start()` and again on a cef retry) (phase `failed`, error `cef_timeout`); `"abort_connect"` when `connecting` lasts `BOOT_CONNECT_TIMEOUT_MS` (phase `failed`, error `connection_timeout`); otherwise `""`. Phase `title` becomes `cef` once the dwell is done but the page is not ready.
   - `func on_connected() -> void` (phase `ready`), `func on_connection_failed(error: String) -> void` (phase `failed`, given error; ignored unless `connecting`).
   - `func retry(now_ms: int) -> String`: only in `failed`; cef errors -> phase `cef`, error null, `page_ready = false`, restart the CEF timer, return `"reload"`; connection errors (incl. `invalid_endpoint`) -> phase `connecting`, error null, restart the connect timer, return `"connect"`; otherwise `""`.
   - `func view() -> Dictionary`: `BootView` keys exactly: `phase`, `buildId`, `progress` (null), `canSkipTitle` (true while a skip would be accepted now; use the last `now_ms` seen), `error`, `canRetry` (`phase == "failed"`).
   - `static func parse_endpoint(user_args: PackedStringArray) -> Dictionary`: `{"host", "port", "ok"}`; default `DEFAULT_SERVER_HOST` + `GameConst.PORT` with `ok = true`; `--connect host:port` (next arg, or `--connect=host:port`) overrides. `ok = false` (host/port = the defaults) when: `--connect` is the last arg or followed by another `--` flag, the value has no `:`, the host is empty (`:7000`, `--connect=`), or the port is not an integer in 1-65535.
   - `static func build_id() -> String`: `ProjectSettings.get_setting("application/config/version", "")`, `"dev"` when empty.
3. `Hud.gd`:
   - Signals `boot_skip_requested`, `boot_retry_requested`, `quit_requested`, `page_ready` (emitted in the `ready` branch, every time).
   - `route_request`: `boot.skip` -> action `["boot_skip"]`, `boot.retry` -> `["boot_retry"]`, `app.quit` -> `["quit"]` (ok reply `{}`); `_on_ipc_message` emits the matching signal.
   - `func show_boot(view: Dictionary) -> void`: `publish("boot", view)`; if `_route != "/splash"` navigate there and `_set_panel_input(true)`.
   - `func end_boot() -> void`: erase the `boot` snapshot, navigate `/`, `_set_panel_input(false)`.
   - `func reload_page() -> void`: `_page_ready = false`; if the browser `has_method("reload")` call it, else set `url` again (`page_url(OS.get_cmdline_user_args())`). Report which path the addon supports.
   - `route_request` gets a `# ponytail:` comment for the deferred `not_available`/`busy` boot errors.
4. `Main.gd` `_start_client`:
   - Keep the view container, Hud creation and signal wiring; connect the new Hud signals (`boot_skip_requested` -> `_boot.skip(now)`, `boot_retry_requested` -> retry handling, `quit_requested` -> `get_tree().quit()`, `page_ready` -> `_boot.on_page_ready(now)` then hide the native fallback if shown). Every boot handler starts with `if _boot == null: return` (`page_ready` fires on every page load, also after boot, e.g. a Vite reload with `--ui-dev`).
   - Endpoint from `BootFlow.parse_endpoint(OS.get_cmdline_user_args())`, stored in a member.
   - `func _connect_to_server() -> void`: if the endpoint is not ok, or `create_client` returns an error: with `_boot` -> `_boot.on_connection_failed("invalid_endpoint")` (endpoint not ok) or `("connection_failed")` (create error) and return; without `_boot` -> `push_error` + `get_tree().quit(1)` as today. Otherwise wire the multiplayer signals once (guard with `is_connected`), set `multiplayer.multiplayer_peer`, print `[Main] Connecting to <host>:<port>`.
   - If `not Hud.can_use_browser()`: call `_connect_to_server()` immediately (today's behaviour).
   - With a browser: `_boot = BootFlow.new()`, `start(now, BootFlow.build_id())`, `_hud.show_boot(_boot.view())`. Do not fail early on a bad endpoint: the flow fails when it reaches `connecting` (keeps the CEF watchdog working).
   - In `_process`, insert the boot block right after the `_server_mode` guard (before the `player == null` early return): while `_boot != null`: `match _boot.tick(now)`: `"connect"` -> `_connect_to_server()`; `"fail_cef"` -> native fallback; `"abort_connect"` -> close the ENet peer, `multiplayer.multiplayer_peer = null`. Then, if `_boot` is still set, push `_hud.show_boot(_boot.view())` only when the view changed (compare `JSON.stringify`); print `[Main] Boot failed: <error>` once when the phase becomes `failed`.
   - `_unhandled_input`: while `_boot != null`, Enter / keypad Enter (pressed, not echo) -> `_boot.skip(now)` and mark the event handled.
   - `_on_connected_to_server`: if `_boot`: `on_connected()`, `_hud.end_boot()`, `_boot = null`. `_on_connection_failed`: if `_boot`: `on_connection_failed("connection_failed")` (keep the existing peer reset).
   - Retry: `_boot.retry(now)` -> `"connect"`: `_connect_to_server()`; `"reload"`: hide the native fallback, `_hud.reload_page()`.
   - Native fallback: `func _show_native_fallback() -> void` builds once a `CanvasLayer` (layer `GameConst.BOOT_FALLBACK_LAYER`) with a full-rect dark `ColorRect`, a centered `Label` "The interface could not load." and `Button` Retry + `Button` Quit (Godot default theme); Retry -> retry handling; Quit -> quit; cursor visible while it shows. Hidden when the page later becomes ready.
   - Update the header comment (connect target, `--connect`).
5. Tests:
   - `tests/main/test_boot_flow.gd`: skip refused before 250 ms and accepted after; `tick` returns `"connect"` only after dwell + page ready (both orders); CEF timeout -> `"fail_cef"` with error `cef_timeout`; a late `on_page_ready` after `cef_timeout` returns to `cef` and the next tick (dwell done) returns `"connect"`; after a cef `retry`, `tick` does not connect until `on_page_ready` again; connect timeout -> `"abort_connect"`, `connection_timeout`; `retry` after `connection_failed` returns `"connect"` and after `cef_timeout` returns `"reload"`; `view()` has exactly the six `BootView` keys and `canRetry` only when failed; `parse_endpoint`: default (ok, 127.0.0.1, PORT), `--connect 10.0.0.2:7000`, `--connect=host:80`, `--connect a:0` (ok false), `--connect` last (ok false), `--connect --ui-dev` (ok false), `--connect=:7000` (ok false, default host/port returned).
