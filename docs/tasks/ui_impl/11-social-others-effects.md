## Decisions for this card (supervisor)
- Settings snapshot: keep both existing pushes unchanged and add two: `_hud.push_settings(_settings.view())` right after `_settings.load()` (the Hud caches it until the page is ready) and at the end of `_on_settings_changed` (every apply and session reset), so the page always has current values. A push before the apply reply is fine (the page store rebases).
- `party_invites` (session, `everyone`/`nobody`), server side: `PartyService` keeps `_invites_blocked: Dictionary` (peer_id -> true). `func set_invites_allowed(peer_id: int, allowed: bool) -> void` (blocking also erases a pending invite addressed to that peer). `invite_to_party` returns false when the target is blocked (after the known-player check), so the inviter gets the existing generic "Cannot invite that player" (the preference stays private). `remove_peer` erases the flag. Accepted limitation: an invite card already on the target's screen stays until it expires (accepting it is refused).
- RPC `server_request_party_invites(allowed: bool)` on `ServerManager` (`@rpc("any_peer", "call_remote", "reliable")`, gate `_can_accept_request(sender)`, not the alive gate: a downed player may change it) -> `_parties.set_invites_allowed(sender, allowed)` and `print("[ServerManager] peer %d party invites %s" % [sender, "everyone" if allowed else "nobody"])`; facade `func request_party_invites(allowed: bool) -> void: _send_client_request("server_request_party_invites", [allowed])` next to the other party facades. Main sends it in `_on_connected_to_server` (every new connection; the session value was reset on disconnect) and in `_on_settings_changed` when `"party_invites"` is in `changed_keys` and `_is_connected()`. `var allowed := String(_settings.values().get("party_invites", "everyone")) == "everyone"`.
- Streamer mode: `static var streamer_mode: bool = false` on `Hud`, set by Main in `_apply_hud_settings`. New GameConst values: `STREAMER_ID_MODULO: int = 100`, `STREAMER_MASK: String = "••"`, `SERVER_ID_MASK: String = "••••"`.
  - `player_name(peer_id)`: on -> `"Player %s%02d" % [GameConst.STREAMER_MASK, peer_id % GameConst.STREAMER_ID_MODULO]` (`Player ••45`); off -> `"Player %d"`.
  - `static func redact(text: String) -> String`: off -> unchanged. On: (1) player IDs: pattern `"\\b([Pp]layer) ([0-9]+)\\b"` (use `[0-9]`, not `\d`, which is an invalid GDScript escape); loop over `search_all(text)`, copy the text between matches, and for each match append `m.get_string(1) + " " + GameConst.STREAMER_MASK + "%02d" % (int(m.get_string(2)) % GameConst.STREAMER_ID_MODULO)`; (2) server ID: `RegEx` `GameConst.SERVER_ID_PREFIX + "[0-9]{4}"` replaced with `GameConst.SERVER_ID_PREFIX + GameConst.SERVER_ID_MASK` via `sub(text, replacement, true)` (all matches). Compile the RegExes once (static vars, lazily).
  - Apply `redact` to every notification text where HudState `notifications` is built (server texts like "Invite sent to player 123" and "Connected to SV-SPACE-0042" go through it). Peer IDs in actions (`peerId` fields) stay unredacted.
  - `PartyService.send_party_state`: change its notification to `"Party: leader player %d, %d members" % [party.leader_id, party.members.size()]` (the old text listed raw peer IDs the regex cannot see; no test asserts it).
  - Accepted limitation: an already open search title is not re-masked when streamer mode is toggled.
- `show_player_names`: no world nameplates yet; stored only. `language`: English only.
- Minimap rotation: `Minimap` gets `var rotate_with_heading: bool = false`, `var heading_yaw: float = 0.0`, `static func camera_rotation(yaw: float, rotate: bool) -> Vector3` = `Vector3(-PI / 2.0, yaw if rotate else 0.0, 0.0)` (default Euler YXZ: yaw first, then the -90 degree pitch, so screen-up is the camera's facing). `_process` sets `_camera.rotation = camera_rotation(heading_yaw, rotate_with_heading)`; keep the `rotation_degrees` line in `_ready`. Hud: `func set_minimap_rotate(on: bool) -> void` (`if _minimap != null: _minimap.rotate_with_heading = on`) and, where it computes `ctx["heading"]`, `if _minimap != null: _minimap.heading_yaw = camera.global_rotation.y` (`_minimap` is null on clients without the browser). Main calls `set_minimap_rotate` from `_apply_hud_settings`.
- Audio buses: `GameConst.AUDIO_BUSES: Dictionary = {"music_volume": "Music", "sfx_volume": "SFX", "ui_volume": "UI"}`. `SettingsApplier.ensure_audio_buses() -> void` adds each missing bus by name (`AudioServer.add_bus()`, `set_bus_name(index, name)`, `set_bus_send(index, AudioServer.get_bus_name(MASTER_BUS))`), idempotent. `static func apply_bus_volume(bus_index: int, volume: int) -> void` (return when `bus_index < 0`; mute at 0, else unmute and `linear_to_db(volume / PERCENT)`), used for master and the three buses. `apply_engine` calls `ensure_audio_buses()`, then applies each present volume key. Delete the old "music/sfx/ui buses do not exist yet" comment and update the `apply_engine` doc comment to "vsync, frame cap, master/music/sfx/ui volume". No sounds play yet; future players pick a bus by these names.
- Not-applied settings (one comment list at the top of `SettingsApplier.gd`, each with its reason): `textures` (restart path not built), `show_player_names` (no nameplates yet), `language` (English only), `voice_*`, `voice_volume`, `muted_players` (voice capability hidden), `chat_filter` and `show_damage_numbers` (coming later), `telemetry`, `crash_reports` (backend capability hidden), `ads_sensitivity`, `aim_mode`, `crouch_mode`, `sprint_mode` (features not built; check the schema for their availability and say it).

## Rules
- `ui/` never references `ServerManager`; Main wires Hud and settings. Features (`PartyService`) never import `ui/`. No magic numbers: new values in `GameConst.gd`. Server requests are validated on the server; the client facade only sends.
- Tests extend `TestCase`, mirror the source tree, no setup/teardown hooks exist, and `Hud.streamer_mode` is shared by every later test file: compute the values, set `Hud.streamer_mode = false`, then assert (a runtime error ends a test method early).
