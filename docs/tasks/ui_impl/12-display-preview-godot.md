# ui_impl 12: display preview transaction in Godot (15 s keep / revert)

Design source: `docs/ui-design/03-settings.md` section 4 "Display preview" state ("Show 15 s confirmation. Revert on timer, Escape, focus loss or host error. Keep commits full patch. Failed save reverts display and leaves draft editable"), `display_mode`/`resolution` rows ("Preview, then Keep"); `docs/ui-design/DATA_CONTRACTS.md` `SettingsView.preview: { token: string; secondsLeft: number } | null`, `saveError: 'load_failed' | 'save_failed' | 'preview_reverted' | null`, rows `settings.apply` (`{previewToken: string | null}`, errors incl. `busy`), `settings.display_confirm` (`{token: string, keep: boolean}` -> `{}`, errors `bad_params`, `preview_expired`, `save_failed`; "Revert restores prior display"), `settings.close` ("revert any preview"), and the closing paragraph ("Display timeout, focus loss or CEF failure reverts even when the page cannot respond"). Card 12b already built the page: it shows the dialog while `view.preview != null`, counts down locally and sends `settings.display_confirm {token, keep}`. Read first: `ui/settings/SettingsService.gd` (`load`, `apply_patch`, `_save`, `view`, `save_error`), `ui/settings/SettingsApplier.gd` (`DISPLAY_KEYS`, `apply_window`), `main/Main.gd` (`_start_client` signal connects, `_on_settings_apply`, `_on_settings_close`, `_on_escape`, `_unhandled_input`, `_process` capture check, `_notification`, `_on_page_ready`, `_on_settings_changed`), `ui/hud/Hud.gd` (`route_request` `settings.display_confirm`, `_on_ipc_message`, `push_settings`, `send_reply`), `lib/constants/GameConst.gd`, `tools/smoke_local.ps1` (clients start with `--position`/`--resolution 960x540`), `tests/ui/settings/test_settings_service.gd` (helpers `_temp_path()`/`_service()`/`_remove()`), `tests/ui/hud/test_hud.gd`.

## Decisions for this card (supervisor)
- `SettingsService` preview state `_preview: Dictionary = {}` (`{"token", "merged", "started_ms"}`); `load()` resets it to `{}`. Token `"p%d" % _next_token` from an incrementing counter.
- `func apply_patch(revision: int, patch: Dictionary, now_ms: int = Time.get_ticks_msec()) -> Dictionary`. First line: `if preview_active(): return _fail("busy")` (before the stale-revision check). Validation then runs exactly as today. A patch previews when, after merging, `display_mode` or `resolution` differs from the current value (`SettingsApplier.DISPLAY_KEYS`; no cycle, same folder): store `_preview = {"token": t, "merged": merged, "started_ms": now_ms}` and return `{"ok": true, "error": "", "data": {"previewToken": t}}`; nothing saved, revision unchanged, `changed` not emitted. Patches without a display change behave exactly as today (`previewToken: null`). Main calls it without `now_ms`.
- Queries: `preview_active() -> bool`, `preview_token() -> String` (`""` when none), `preview_values() -> Dictionary` (merged values; `{}` when none), `preview_expired(now_ms: int) -> bool` (active and `now_ms - started_ms >= GameConst.DISPLAY_PREVIEW_MS`), `auto_revert_due(now_ms: int, settings_open: bool) -> bool` = `preview_active() and (preview_expired(now_ms) or not settings_open)`.
- `view(now_ms: int = Time.get_ticks_msec())`: `preview` = `{"token": t, "secondsLeft": max(0, ceili((DISPLAY_PREVIEW_MS - (now_ms - started_ms)) / 1000.0))}` or `null`. Remove the old `ponytail` comment there.
- `confirm_preview(token: String, keep: bool, now_ms: int = Time.get_ticks_msec()) -> Dictionary` (`{"ok", "error"}`): no active preview or a different token -> `{ok: false, error: "preview_expired"}` (a running preview with another token is left untouched); expired at `now_ms` -> `revert_preview()` and `preview_expired`; `keep == false` -> drop the preview, `save_error = null`, ok; `keep == true` -> `_save(merged)`; failure -> drop the preview, `save_error = "save_failed"`, return `save_failed`; success -> commit exactly like a normal apply (values, revision + 1, `save_error = null`, emit `changed` with the changed keys), ok.
- `revert_preview() -> void` (automatic: timer, focus loss, Settings no longer open, page reload): no-op when none; else drop the preview and `save_error = "preview_reverted"`. The next successful apply or keep clears `save_error` (already true for apply).
- Window restore uses the real prior window, not stored values (startup may have skipped the display keys, e.g. the smoke flags). Main: `var _preview_window: Dictionary = {}`. Right before applying a preview, store `{"mode": DisplayServer.window_get_mode(), "size": DisplayServer.window_get_size(), "position": DisplayServer.window_get_position()}`, then `SettingsApplier.apply_window(_settings.preview_values(), SettingsApplier.DISPLAY_KEYS)`. `func _restore_preview_window()`: return when empty; `window_set_mode(mode)`; when the mode is `WINDOW_MODE_WINDOWED` also `window_set_size(size)` and `window_set_position(position)`; clear it. A kept preview only clears `_preview_window` (the existing `_on_settings_changed` applies the kept values). Do not change `SettingsApplier`.
- Ordering rule for the page: push the snapshot (`_hud.push_settings(_settings.view())`) BEFORE the matching reply, for apply and display_confirm, and push after every automatic revert (no reply). A failed `settings.apply` keeps today's behaviour (reply only, no push).
- Main helpers:
  - `_revert_preview()`: `if _settings == null or not _settings.preview_active(): return`; `_settings.revert_preview()`; `_restore_preview_window()`; push.
  - `_cancel_preview()` (explicit, Esc): `_settings.confirm_preview(_settings.preview_token(), false)`; `_restore_preview_window()`; push.
  - `_on_settings_display_confirm(request_id: int, token: String, keep: bool)`: `var was_active := _settings.preview_active()`; `var r := _settings.confirm_preview(token, keep)`; `if was_active and not _settings.preview_active() and not (keep and bool(r["ok"])): _restore_preview_window()`; `if keep and bool(r["ok"]): _preview_window = {}`; push; `_hud.send_reply(request_id, bool(r["ok"]), {}, String(r["error"]))`.
- Triggers: `_process` right after the capture check: `if _settings != null and _settings.auto_revert_due(Time.get_ticks_msec(), _hud.is_settings_open()): _revert_preview()`. `NOTIFICATION_APPLICATION_FOCUS_OUT` -> `_revert_preview()`. `_on_settings_close` -> `_revert_preview()` before closing. `_on_page_ready` -> `_revert_preview()` on the line right after `_finish_capture(null)` (before the `_boot == null` return; the Hud replays the cached snapshot before `page_ready`, so this push comes after it).
- Escape: in `_unhandled_input`, directly before `if _boot != null or _lobby != null: return` (so it also works when Settings was opened from the lobby): `if key_event.physical_keycode == KEY_ESCAPE and _settings != null and _settings.preview_active() and _hud.is_settings_open(): _cancel_preview(); get_viewport().set_input_as_handled(); return`. `_on_escape` keeps ignoring Esc over Settings; update its `ponytail` comment to say a preview's Esc is handled in `_unhandled_input`.
- Hud: `settings.display_confirm` with String `token` and bool `keep` -> `{"reply": null, "action": ["settings_display_confirm", id, token, keep]}`, else `bad_params`; `_on_ipc_message` emits new signal `settings_display_confirm_requested(request_id: int, token: String, keep: bool)`; remove the old `ponytail` comment. Main connects it in `_start_client` after the `settings_capture_cancel_requested` connect.
- The `ponytail` line about the preview in `SettingsApplier.apply_window`'s doc comment: delete only that line.

## Rules
- `ui/settings/` is client-only; `ui/` never references `ServerManager`; Hud emits signals, Main wires them. No magic numbers: `GameConst.DISPLAY_PREVIEW_MS`. Tests extend `TestCase`, mirror the source tree, have no setup/teardown hooks, use temp config paths (never the real `user://settings.cfg`), and must not resize a real window (test `SettingsService` and `Hud.route_request` only).
