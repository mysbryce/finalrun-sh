## Decisions for this card (supervisor)
- Store `features/hud/overlayStore.ts` (zustand): `{ transfer: TransferView | null; overlay: GameOverlayView | null; setTransfer; setOverlay }`. `main.tsx` passes `setTransfer` and `setGameOverlay` to `installBridge`.
- Godot owns the route; the page renders by route and store. The receipt's lifetime is host-owned: the page shows `overlay` until a `null` arrives and keeps no timer of its own.
- `router.tsx`: the `/` route component becomes `ReceiptCard`; new routes `/death` and `/arrest` -> `ReceiptScreen`, `/transfer` -> `TransferScreen`. Move the HUD visibility check into a pure exported helper `showsHud(pathname: string): boolean` in `app/showsHud.ts` (false for `/inventory`, `/splash`, `/lobby`, `/settings/*`, `/death`, `/arrest`, `/transfer`; true otherwise) used by `RootLayout`, with a test.
- `layout.ts` px constants, all in screen px (1280 × 720). Rows the spec centres keep top/width/height and are centred like the existing rows (`left-1/2 -translate-x-1/2`): `OVERLAY_PANEL` { left 408, top 238, width 464, height 244 }; `OVERLAY_TITLE` top 262 h 32, `OVERLAY_SUMMARY` top 306 h 44, `OVERLAY_STATUS` top 362 h 32, `OVERLAY_PROGRESS` top 402 h 12, `OVERLAY_FOOTER` top 418 h 40 (each width 416); `RECEIPT_CARD` { left 416, top 260, width 448, height 164 } with `RECEIPT_TITLE` top 272 h 28, `RECEIPT_SUMMARY` top 308 h 44, `RECEIPT_HINT` top 368 h 40 (width 416); `DOWNED_PANEL` { left 416, top 260, width 448, height 188 } with `DOWNED_TITLE` top 272 h 28, `BLEED_OUT` top 308 h 12, `DOWNED_CONTROLS` top 416 h 20 (width 416). `BLEED_OUT_SECONDS = 60` with a comment that it matches `GameConst.DOWNED_BLEEDOUT_SECONDS`.
- Positioning rule (applies to every new surface): the screen root is `fixed inset-0` (or the existing HudScreen root); the panel/card is an absolutely positioned background box (`Panel` with `inset={0}` and `style` from the constant, or a plain div); the rows are SIBLINGS of that box, absolutely positioned with the screen-px constants. Never nest rows inside the panel with screen-px tops. `HudScreen` renders `<DownedPanel />` and the existing `<DownedChannels />` side by side, not nested.
- Copy lives in `features/hud/outcomeCopy.ts` as pure functions (tested): `outcomeTitle(v: GameOverlayView): string`, `outcomeSummary(v: GameOverlayView): string[]` (one or two lines), `outcomeStatus(v: GameOverlayView): string`, `transferTitle(t: TransferView): string`, `transferSummary(t: TransferView): string`, `transferStatus(t: TransferView): string`. Strings:
  - Title: death `You died`; arrest `Arrested`.
  - Cause: `bleed_out` `You bled out.`; `finished` `You were finished off.`; `other` `You were killed.`; `surrender` `You surrendered to the police.`; `cuffed` `You were cuffed.`. Arrest adds a second summary line `Bag forfeited · gear kept` when both flags are true.
  - Status: death `Respawning at <destination>.`; arrest `Returning as Citizen to <destination>.`.
  - Transfer title: reason `join` -> `Joining <mapName>`, otherwise `Travelling to <mapName>`; stage `failed` -> `Transfer failed`.
  - Transfer summary by reason: `join` `Entering the session.`; `travel` `Map transfer.`; `extract` `Extracted from LootyBay.`; `death` `You died. Respawning at Motel.`; `arrest` `Arrested. Returning as Citizen to Motel.`.
  - Transfer status: `loading` `Loading map…`; `waiting_for_spawn` `Waiting for the server…`; `failed` by error: `transfer_timeout` `The server did not confirm the transfer in time.`, `map_load_failed` `The map could not be loaded.`, `disconnected` `Lost connection to the server.`, null `Transfer failed.`.
- World dim (A01 of the death/arrest/transfer drawings): a `fixed inset-0 bg-zinc-950/55` div (same as `Modal`'s backdrop).
- `ReceiptScreen` (`/death`, `/arrest`; renders nothing when `overlay` is null): world dim with `data-testid="overlay-dim"`, the panel box at `OVERLAY_PANEL`, then the rows: title (`OVERLAY_TITLE`), summary lines (`OVERLAY_SUMMARY`), status (`OVERLAY_STATUS`) and a footer row (`OVERLAY_FOOTER`) with a `Button` `Dismiss` plus `<KeyHint k="Esc" label="Dismiss" />`. A click on the dim sends `request('overlay.dismiss', { receiptId })`; the panel box and the rows call `stopPropagation` in `onClick` so a click on them never reaches the dim; the button sends the same request once. Ignore request errors (an expired id is a no-op on the host). The title row has `role="status"` so screen readers announce the outcome once.
- `ReceiptCard` (`/`; nothing when `overlay` is null): the compact card box at `RECEIPT_CARD` with title (`RECEIPT_TITLE`), summary lines (`RECEIPT_SUMMARY`) and the hint row (`RECEIPT_HINT`) `Esc or click to dismiss` (plain text: the cursor is captured on `/`, Godot does the dismissal). Whole card `pointer-events-none`.
- `TransferScreen` (`/transfer`; nothing when `transfer` is null): world dim (no click handler) + panel box + rows for title, summary and status by the copy above; the status row has `role="status"`, or `role="alert"` when failed.
  - Failed: footer row holds a primary `Button` `Return to Lobby` that sends `request('transfer.return_to_lobby', {})`. While pending it shows `loading` (which also disables it); on success keep `loading` (Godot routes away); on an error reply the status row shows `Could not return to the lobby.` instead of the status text and the button is enabled and focused again. Focus the button when it appears (wrap it in a div ref and focus its inner `button` in an effect; Godot also maps Enter to it). Clear the error when `transfer` changes.
  - Not failed: footer row holds a `StageRail` with `Load map` and `Spawn`: `loading` -> current/pending, `waiting_for_spawn` -> done/current. `StageRail` is fixed at 448 px wide; it may stick out of the 416 px row, that is fine. When `progress` is a number, a `ProgressBar` at `OVERLAY_PROGRESS` with `label="Map loading"`, `value={progress}`, `max={1}`, default size. (Godot sends null today.)
  - Deliberate deviation from "retains a current receipt above loading": on `/transfer` the receipt card is not drawn, because it would cover the panel; the transfer summary row (reason `death`/`arrest`) carries the outcome, and the receipt shows again on `/` if it is still alive.
- Downed panel (replaces `BleedOutBanner`, which is deleted; this also fixes its overlap with the toast tray): `DownedPanel({ seconds }: { seconds: number | null })`, rendered by `HudScreen` while `hud.life === 'DOWNED'` with `seconds={hud.timer?.seconds ?? null}`. Panel box at `DOWNED_PANEL`; title row at `DOWNED_TITLE` with `role="status"` and markup `Downed<span aria-hidden="true"> · <span>{Math.ceil(seconds)} s</span></span>` (when `seconds` is null the inner span shows `—`), so the live region only reads "Downed"; `ProgressBar` at `BLEED_OUT` with `label="Bleed-out"`, `value={seconds ?? undefined}`, `max={BLEED_OUT_SECONDS}`, default size (null renders the indeterminate stripes and the word "Working"; expected); controls row at `DOWNED_CONTROLS`: `Crawl to cover · wait for a revive`. No colour-only meaning. Hiding the hotbar and interact card while downed (visibility matrix) is out of scope for this card.
- `demoOverlay.ts` with `DEMO_RECEIPT_DEATH`, `DEMO_RECEIPT_ARREST`, `DEMO_TRANSFER` (loading, join, Motel) and `DEMO_TRANSFER_FAILED` (`transfer_timeout`); `main.tsx` dev hashes `#death`, `#arrest`, `#receipt` (death receipt on `/`), `#transfer`, `#transfer-failed`.
